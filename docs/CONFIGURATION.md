# OtHoneypot configuration reference

The application reads configuration from `OtHoneypot.Service/appsettings.json`. Environment-specific files such as `appsettings.Development.json` override matching values. Enum values are written as their names and are case-insensitive.

## Top-level sections

| Path | Type | Required | Description |
|---|---|---:|---|
| `Serilog` | object | no | Console and file logging configuration. |
| `Honeypot` | object | yes | Honeypot simulation and protocol configuration. |
| `Honeypot:DataTemplates` | array | no | Values generated by the simulation service. |
| `Honeypot:Modbus` | array | no | Modbus TCP master and slave modules. |

## Data templates

Each item in `Honeypot:DataTemplates` defines one process value.

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `Id` | integer | yes | unique | Identifier referenced by slave `Registers` and `CommandMappings`. |
| `Name` | string | yes | unique, non-empty | Value name used in logs and lookup. |
| `Description` | string | no | empty | Human-readable description. |
| `DataType` | string | no | currently informational | Simulation values are currently stored internally as `float`. The Modbus register's `DataType` controls wire encoding. |
| `Simulation` | object | yes | — | Generation rules described below. |

### Simulation options

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `MinValue` | number | yes | must be `<= MaxValue` | Lower bound and reset/start value for `Static` and `Dynamic`. |
| `MaxValue` | number | yes | must be `>= MinValue` | Upper bound. |
| `RefreshRate` | integer | yes | seconds, `> 0` | Time between generated updates. |
| `Type` | enum | yes | see below | Simulation algorithm. |
| `ValueChangeRate` | number | conditional | default `1`, must be `>= 0` | Maximum RandomWalk step or exact Dynamic step per refresh. |

Implemented simulation types:

| `Type` | Start value | Behavior |
|---|---|---|
| `Static` | `MinValue` | Keeps the same value. |
| `Random` | random in range | Generates an independent random value on every refresh. |
| `RandomWalk` | random in range | Adds a random step between `-ValueChangeRate` and `+ValueChangeRate`, clamped to the configured range. |
| `Dynamic` | `MinValue` | Reacts to `Increase`, `Decrease`, `Hold`, and `Reset` commands. |

`Sine` and `Counter` exist in the enum but are not implemented yet; selecting either stops startup with `NotSupportedException`.

## Modbus module

Each item in `Honeypot:Modbus` creates one independent module.

| Option | Type | Required | Values/default | Used by | Description |
|---|---|---:|---|---|---|
| `Name` | string | yes | — | both | Module name used in logs. |
| `Description` | string | no | empty | both | Human-readable description. |
| `Enabled` | boolean | yes | `false` | both | Disabled modules are not created. |
| `Type` | enum | yes | `ModbusTcp` | both | Protocol type. For this module use `ModbusTcp`. |
| `Role` | enum | yes | `Master` or `Slave` | both | Selects polling or server behavior. |
| `BindAddress` | string | slave | `0.0.0.0` | slave | Local address on which the slave listens. |
| `Port` | integer | slave | conventionally `502` | slave | Listening TCP port. Ports below 1024 may require elevated OS privileges. |
| `UnitId` | byte | no | `1` | slave | Slave/unit identifier, from 0 through 255. |
| `AllowedIPs` | string array | no | empty | slave | IPs/CIDRs for which the security warning is suppressed. It never blocks traffic. Empty means every connection produces an alert. |
| `ReadingInterval` | integer | no | master `1000`, slave `250` | both | Delay in milliseconds between master polling cycles or slave register/command scans. Values `<= 0` use the role-specific fallback. |
| `Devices` | array | master | empty | master | Remote slaves to poll. |
| `Registers` | array | slave | empty | slave | Simulated slave register map. |
| `CommandMappings` | array | slave | empty | slave | Writable values mapped to Dynamic simulation commands. |

### Master devices

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `Name` | string | yes | — | Remote device name used in logs. |
| `IPAddress` | string | yes | hostname or IP | Remote Modbus TCP endpoint. |
| `Port` | integer | no | `502` | Remote TCP port. |
| `UnitId` | byte | no | `1` | Remote slave/unit identifier. |
| `PollIntervalMs` | integer | no | currently unused | Reserved for a per-device interval. `ReadingInterval` currently controls the polling cycle. |
| `Polls` | array | yes | — | Register ranges to read. |
| `ScheduledWrites` | array | no | empty | Holding Register or Coil writes sent according to a timer. |

### Master polls and parsed values

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `Name` | string | yes | — | Poll name included in parsed-value logs. |
| `RegisterType` | enum | yes | see below | Table to read. |
| `StartAddress` | unsigned 16-bit integer | yes | `0`–`65535` | Zero-based protocol address. |
| `Count` | unsigned 16-bit integer | yes | number of 16-bit registers/bits | For numeric register values this must be divisible by registers per value. For `String`, it is the total string capacity in registers. |
| `DataType` | enum | no | `UInt16` | How Input/Holding register words are decoded. Ignored for Coil/DiscreteInput. |
| `ByteOrder` | enum | no | `ABCD` | Byte/word order for multi-register values. |
| `PollIntervalMs` | integer | no | currently unused | Reserved for a per-poll interval. `ReadingInterval` currently controls the polling cycle. |

Register types:

| Value | Modbus table | Writable |
|---|---|---:|
| `Coil` | coils | yes |
| `DiscreteInput` | discrete inputs | no |
| `InputRegister` | input registers | no |
| `HoldingRegister` | holding registers | yes |

Master register data types:

| `DataType` | Registers per value | .NET result |
|---|---:|---|
| `Int16` | 1 | `short` |
| `UInt16` | 1 | `ushort` |
| `Int32` | 2 | `int` |
| `UInt32` | 2 | `uint` |
| `Float32` | 2 | `float` |
| `Int64` | 4 | `long` |
| `UInt64` | 4 | `ulong` |
| `Float64` | 4 | `double` |
| `String` | entire poll | ASCII string; trailing NUL bytes are removed |

For a 32-bit value whose canonical bytes are `A B C D`, `ByteOrder` supports `ABCD`, `BADC`, `CDAB`, and `DCBA`. For 64-bit values the same rule is extended across four 16-bit words: byte-swap, word-reverse, both, or neither.

Example: two Float32 values at addresses 100–103:

```json
{
  "name": "Temperatures",
  "registerType": "HoldingRegister",
  "startAddress": 100,
  "count": 4,
  "dataType": "Float32",
  "byteOrder": "CDAB"
}
```

### Master scheduled writes

Each item in a device's `ScheduledWrites` array is evaluated during the normal master polling cycle.

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `Name` | string | yes | empty | Write name included in logs and error messages. |
| `RegisterType` | enum | yes | `HoldingRegister` | Must be `HoldingRegister` or `Coil`. |
| `Address` | unsigned 16-bit integer | yes | `0`–`65535` | Zero-based remote address. |
| `Value` | unsigned 16-bit integer | yes | `0`–`65535` | Register value. Coil writes accept only `0` or `1`. |
| `InitialDelayMs` | integer | no | `0`, must be `>= 0` | Delay measured from the first successful connection to the device. |
| `RepeatEveryMs` | integer | no | `0`, must be `>= 0` | Interval between writes. Zero means that the write runs once. |

The actual timing resolution is limited by the module's `ReadingInterval`, because scheduled writes are checked when the device is polled. For example, with a 1000 ms reading interval, a write scheduled for 5500 ms normally runs during the poll at approximately 6000 ms.

Example that alternates the slave's TankLevel simulation between `Increase` and `Hold`:

```json
"ScheduledWrites": [
  {
    "Name": "StartFilling",
    "RegisterType": "HoldingRegister",
    "Address": 200,
    "Value": 1,
    "InitialDelayMs": 5000,
    "RepeatEveryMs": 60000
  },
  {
    "Name": "StopFilling",
    "RegisterType": "HoldingRegister",
    "Address": 200,
    "Value": 3,
    "InitialDelayMs": 30000,
    "RepeatEveryMs": 60000
  }
]
```

This produces `Increase` at approximately 5, 65, 125… seconds and `Hold` at approximately 30, 90, 150… seconds. The slave mapping determines what values `1` and `3` mean.

### Slave registers

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `Name` | string | yes | — | Register name used in errors/logs. |
| `Type` | enum | yes | register type table above | Destination Modbus table. |
| `Address` | unsigned 16-bit integer | yes | `0`–`65535` | Zero-based protocol address. |
| `DataType` | enum | yes | `Bool`, `Int16`, `UInt16`, `Int32`, `UInt32`, or `Float32` | Encoding written into the datastore. Other enum values are not implemented on the slave side yet. |
| `Writable` | boolean | no | currently informational | Command writes are handled through `CommandMappings`. |
| `DataTemplateId` | integer | yes | existing template ID | Generated value to expose. |
| `Value` | any | no | currently unused | Runtime values come from `DataService`. |

Coil and DiscreteInput entries must use `Bool`. InputRegister and HoldingRegister entries use one register for 16-bit types and two registers for 32-bit types. Slave multi-register encoding is currently `ABCD`.

### Command mappings

Command mappings observe writable slave addresses without blocking or changing normal Modbus behavior.

| Option | Type | Required | Values/default | Description |
|---|---|---:|---|---|
| `Name` | string | yes | empty | Command name used in logs. |
| `RegisterType` | enum | yes | `HoldingRegister` | Must be `HoldingRegister` or `Coil`. |
| `Address` | unsigned 16-bit integer | yes | — | Address watched for changes. |
| `Value` | unsigned 16-bit integer | yes | — | Value that triggers this mapping (`0` or `1` for Coil). |
| `DataTemplateId` | integer | yes | existing template ID | Target simulation. Usually a `Dynamic` template. |
| `Command` | enum | yes | `Hold`, `Increase`, `Decrease`, `Reset` | Action sent to the simulation service. |

Several mappings may share one HoldingRegister address, for example `1 = Increase`, `2 = Decrease`, `3 = Hold`, and `4 = Reset`. A mapping triggers only when the address changes to its configured value.

## Runnable master and slave example

Two complete example files are included:

- [`appsettings.Slave.example.json`](../OtHoneypot.Service/appsettings.Slave.example.json) starts `ExamplePLC` on `127.0.0.1:1502`, Unit ID `1`. It exposes TankLevel as Float32 at holding registers 100–101 and Pressure as Float32 at 102–103. Holding register 200 accepts Dynamic commands for TankLevel: `1 = Increase`, `2 = Decrease`, `3 = Hold`, and `4 = Reset`.
- [`appsettings.Master.example.json`](../OtHoneypot.Service/appsettings.Master.example.json) connects to that slave, parses the four registers starting at address 100 as two `Float32` values in `ABCD` order, sends `Increase` after 5 seconds, and sends `Hold` after 30 seconds. This 60-second cycle then repeats.

To run both on the same computer, open two terminals. Each process needs its example copied to the active `appsettings.Development.json` before it starts.

Terminal 1 — slave:

```bash
cp OtHoneypot.Service/appsettings.Slave.example.json OtHoneypot.Service/appsettings.Development.json
dotnet run --project OtHoneypot.Service
```

Terminal 2 — master, after the slave has started:

```bash
cp OtHoneypot.Service/appsettings.Master.example.json OtHoneypot.Service/appsettings.Development.json
dotnet run --project OtHoneypot.Service
```

If both processes use the same working tree, copying the second file while the first process is already running is safe: configuration is read during startup and is not reloaded by the application. Alternatively, run each process from a separate checkout.

The example master now both polls values and exercises the slave command mappings. You can also use an external Modbus client to write command values to holding register 200 manually.

## Complete minimal example

```json
{
  "Honeypot": {
    "DataTemplates": [
      {
        "Id": 1,
        "Name": "TankLevel",
        "Description": "Simulated tank level",
        "DataType": "float",
        "Simulation": {
          "MinValue": 0,
          "MaxValue": 100,
          "RefreshRate": 1,
          "ValueChangeRate": 0.5,
          "Type": "Dynamic"
        }
      }
    ],
    "Modbus": [
      {
        "Name": "FakePLC",
        "Type": "ModbusTcp",
        "Description": "Modbus TCP honeypot slave",
        "Enabled": true,
        "Role": "Slave",
        "BindAddress": "0.0.0.0",
        "Port": 502,
        "UnitId": 1,
        "AllowedIPs": ["127.0.0.1", "192.168.10.0/24"],
        "ReadingInterval": 250,
        "Registers": [
          {
            "Name": "TankLevel",
            "Type": "HoldingRegister",
            "Address": 100,
            "DataType": "Float32",
            "Writable": false,
            "DataTemplateId": 1
          }
        ],
        "CommandMappings": [
          { "Name": "LevelUp", "RegisterType": "HoldingRegister", "Address": 200, "Value": 1, "DataTemplateId": 1, "Command": "Increase" },
          { "Name": "LevelDown", "RegisterType": "HoldingRegister", "Address": 200, "Value": 2, "DataTemplateId": 1, "Command": "Decrease" },
          { "Name": "LevelHold", "RegisterType": "HoldingRegister", "Address": 200, "Value": 3, "DataTemplateId": 1, "Command": "Hold" },
          { "Name": "LevelReset", "RegisterType": "HoldingRegister", "Address": 200, "Value": 4, "DataTemplateId": 1, "Command": "Reset" }
        ]
      }
    ]
  }
}
```

## Common configuration errors

- `DataTemplate.Id` or `Name` is duplicated.
- A register or command mapping references a missing `DataTemplateId`.
- `MinValue` is greater than `MaxValue`, `RefreshRate` is not positive, or `ValueChangeRate` is negative.
- A master `Count` is not divisible by the selected numeric datatype width; for example, `Float32` needs an even count.
- A scheduled write targets a read-only table, has a negative delay/interval, or writes a Coil value other than `0` or `1`.
- A slave bit table uses a datatype other than `Bool`.
- The process lacks permission to listen on TCP/502. Use a higher unprivileged port during development or grant the service the required OS capability.
- Display addresses such as `40001` are not protocol offsets. Configure the zero-based offset expected by NModbus (often `0` for displayed register `40001`).
